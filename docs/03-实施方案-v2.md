# WhereSpend 实施方案 v2（已落地）

> 本文回答两个关键问题并记录架构决策。系统已实现并跑通端到端验证。

## 1. 两个关键问题的回答

### Q1：飞书 + 语音 + 一句话，能做到吗？
**能，已全部打通。** 记录侧两条路都支持：

| 方式 | 路径 | 状态 |
|---|---|---|
| 输入框语音输入（推荐） | 飞书客户端自带语音转文字 → bot 直接收到文本 | 天然支持，零额外链路 |
| 直接发语音消息 | bot 下载 opus → ffmpeg 转 16k pcm → 飞书 ASR `speech_to_text` → 文本 | API 已实测（识别「午饭35块，打车12块」准确） |

文本进入后统一走：**DeepSeek 结构化抽取（JSON：金额/事项/类型/分类/账户/日期）→ 写多维表格 → 回执**。实测「京东买书128用白条」→ 学习/京东白条/京东，一次到位。

### Q2：仅靠多维表格，手机端能方便查看筛选吗？
**能，但不必只靠它。** 落地为两层：

1. **飞书多维表格 App**（保底）：表格本身支持视图筛选、分组统计、仪表盘，手机端可用；数据就在表里，随时手动改。
2. **自建移动端 Web 账本**（主力体验）：零依赖单页应用，概览/明细筛选/统计图表三页，可添加到 iPhone 主屏当 PWA 用。明细页支持时间段（本月/上月/本周/今天/全部）× 类型 × 分类 × 账户 × 关键词任意组合筛选，全部本地即时计算。

## 2. 架构（已实现）

```
飞书私聊机器人 ──WebSocket 长连接（无需公网 IP）──┐
   文本消息 / 语音消息(opus)                        │
                                                  ▼
                                    src/index.js 单进程服务
        ├── 语音：ffmpeg 转 pcm → 飞书 ASR
        ├── 解析：DeepSeek（JSON Schema 约束）→ 规则引擎兜底
        ├── 账本：飞书多维表格 API（唯一数据源，随时导出）
        └── 回执/查询问答：im 消息接口
                                                  ▼
                      HTTP :7610 ── /api/records + Web 账本（PWA）
```

关键决策：

- **多维表格是唯一存储**。没有本地数据库，不存在双写不一致；Web 端 15s 内存缓存 + 60s 自动刷新。
- **转账/还款不计入消费统计**（复式记账思想的最小化移植），一笔消费只记一次，渠道只是字段——痛点从记账主体上消失。
- **LLM 只处理单句文本**，不发送任何身份信息；DeepSeek 挂了自动回落规则解析器（正则 + 关键词表，10 个单测覆盖），记账不中断。
- **确定性指令走规则**（改/删/帮助），模糊语句走 LLM，单次调用完成意图识别 + 抽取。
